## §2 上线定义（冻结项 + 决策点）
- **TICK_FEED_ENABLED**：`0` → `1`，启用 L2 `TickFeedConnector`，信号接执行层。
- **eb 接入**：edge 信号按分层契约（R1 风险层单向否决 / R2 同向仅优化进场 / R3 反向弃单 / R5 留痕）
  进入执行层；冲突裁决不改。
- **jd/lh**：保持冻结——上线时作为 **A/B 决策**（非默认剔除）：
  - 源2 `SYMBOLS_SRC2`、M4 `backend_tqsdk.py` `SYMBOL_MAP` 是否保留 jd/lh。
  - A/B 设计见 §4。

## §3 灰度四阶段（逐阶段 Ken 拍板放行）
- **阶段0（当前）**：纯影子。`TICK_FEED_ENABLED=0`，只数信号、不算命中率（edge 预注册 §7.2）。
- **阶段1（主终点PASS后）**：影子 + 真实 tick 回放。`TICK_FEED_ENABLED=1` 但 `eb` **不接实盘**，
  仅内部对照「模拟信号 vs 真实成交滑点」。观察真实滑点是否吞噬 edge。
- **阶段2**：小资金实盘。单信号最小头寸（如 1 手/品种），`eb` 接执行层，**每笔人工复核**。
- **阶段3**：常态化。达到预设风险预算后按 §5 阈值放大。

## §4 jd/lh A/B 设计（上线时触发，非测量期）
- 同一信号源切分：一半交易日**含** jd/lh / 一半**不含**（时间 halves），或按品种 halves。
- 对比指标：实盘成交率、滑点、信号行为偏离预注册 band。
- 样本足（建议 ≥ 30 交易日/组）后判定：剔除组显著更优 → 永久剔除；反之保留。

## §5 下线 / 熔断条件（自动）
- 实盘阶段若 P0-G* 任一 FAIL，或 edge 信号行为偏离预注册 band → **自动回退阶段1 + 告警**。
- jd/lh A/B 结论触发 → 改 `SYMBOL_MAP`/`SYMBOLS_SRC2` 并重新预注册新口径。

## §6 监控 provision（P0 样本累积）
- P0 样本累积由 `shadow_spread_daily.csv` 天然记录；判定日由 P0-G2 触发「换长历史源」（§6.1）。
- 每周自动周检：统计 `n_samples≥61` 品种数 / 18，若自 10-08 起满 ~30 日仍 < 12/18 →
  自动告警「预热过慢，建议启动 §6.1 换源」。该监控为独立 recurring 自动化。
