## 0. 一句话诊断

**核心判断引擎是这套系统真正的资产，账户层和调度层是它最大的负债。**

## 2. 必须保留的核心能力（附证据）

这七项是系统的真实价值，后续任何重构都不得破坏。

### 2.1 前视偏差隔离 —— 最值钱的一条

HMM / GARCH / 情绪 / 宏观 / SR 五个调制器**严格 live-only**，回测路径传 `None`，永不进入。
位置：`four_dim_strategy.py:2854-2856, 3104, 3126, 3131, 3137, 3146`

> 为什么保留：绝大多数自建量化系统死在这一步——回测漂亮、实盘崩。这套系统把防线写进了代码结构而不是靠自觉。重构时若把这五个调制器挪进 `evaluate()` 公共路径，回测立刻失真且**不会报错**。

### 2.2 F/C 独立否决权（`bias_FC`）

`bias_FC = F_w·F + C_w·C`，**刻意排除 T**，用于对技术面一票否决（`|bias_FC| >= fc_hard` 且方向与 `dir_T` 相反）。
位置：`four_dim_live_runner.py:3175`、硬否决 @3191

> 为什么保留：这是"三感"方法论里唯一真正的原创设计——避免"技术面自己证明自己"。多数三维系统把三维加权求和，就等于让权重最大的那一维独裁。

### 2.3 四层风控漏斗 + KillSwitch 不洗白

品种级（`DISABLED_SYMBOLS`）→ 信号级（`risk_gate`）→ 组合级（VaR / 相关性桶 / 板块集中）→ 账户级（状态机 + KillSwitch + 回撤）。
KillSwitch 落盘 `killswitch_state.json`，跨重启不洗白，**自动只能触发、人工只能解除**。

> 为什么保留：层次递进且最内层不给人"重启糊弄过去"的空间。这一条比大多数商业风控产品做得干净。

### 2.4 成本内化

- 滑点按流动性 A/B/C 三档（1.0 / 1.5 / 2.0 tick），按 60 日日均成交额实测量化重排
- 手续费逐笔扣除，净值 / R 倍数 / 期望值均为**净数字**
- 成交质量回灌：`_fill_quality()` 算不利滑点、超预算滑点、滑点占 R%

> 为什么保留：这是"策略能不能实盘"的唯一诚实度量。1m SAR 被判死刑靠的就是这一层。

### 2.5 基准回归测试

`tests/test_baseline_regression.py` + `_baseline_values.json`——防止信号行为被静默改坏。

> 为什么保留：3,368 个测试里这一组最有价值。重构时它就是安全网。

### 2.6 信号可解释性

每个信号输出自然语言理由（T_5m、regime、bias_G、资金确认、手数、止损、分批计划）。

> 为什么保留：没有理由的信号无法复盘，也无法判断"这次是系统对还是运气"。

### 2.7 半自动边界

主链路（runner / strategy / execution_planner）**无任何 `insert_order` / `set_target_volume`**，TqApi 仅出现在取数与回测探针。

> 为什么保留：这条边界让系统出错时的最大损失可控。任何"自动下单"提议在接入券商 API 前都不该被批准。

## 3. 冗余与低效（按危害排序）

### 🔴 R1 账户层：四套账本，三套是死的，sizing 锚在硬编码

实测 `account_state.json`（2026-11-06 10:24）：

```json
{"equity": 0.0, "realized_pnl": 0.0, "positions": {},
 "equity_live": 0.0, "initial_balance": 0.0}
```

**这个文件全程是零。** 现状是四套并行账本：

| 账本 | 状态 | 用途 |
|---|---|---|
| `account_state.json` | **equity=0、positions={}，死** | 名义上的主账户真实持仓 |
| `paper_account.json` | **文件不存在** | 手动模拟盘沙盒 |
| `pti` (paper_trading_state.json) | **活，7.1 KB，4 腿** | 模拟自动跟信号 |
| `tri` | 空 | 三感实盘跟踪 |

后果链条（可验证）：
1. `_sync_live_equity()` @256 取 `am.get_account()` → 恒 `None`（`account_monitor.json` 不存在）
2. 回退 `_account_equity()` → 读到 `equity_live = 0.0`
3. 再回退 `_SIZING_EQUITY_STATIC` → **`/api/state` 的 `sizing_equity` 恒为 `{equity: 1000000.0, source: "static_fallback"}`**
4. 于是 `risk_gate` 里 `N_risk = 权益 × risk_pct% ÷ …` 的"权益"是硬编码常量
5. **1% 单笔风险、45% 使用率、5% 日亏、15% 回撤全部锚在这个假数字上**

> 这不是美观问题。11-01 那次"治本"（account_state → equity_live → snapshot 三级回退）在 account_state 全零的前提下依然落到 static，说明修复没打穿。这条与 11-05 观测到的 `/api/account?fresh=1` 冷算 25–38 秒同源——它在反复尝试读一个永远读不到的后端。

### 🔴 R2 主循环 72–105 秒，且无耗时埋点

`POLL_SEC = 60`，实测周期 72 / 83 / 86.9 秒，峰值 105.6 秒。看门狗 180 秒 `os._exit(3)`。

机制推断（未做相位实测，标注为假设）：
- `evaluate()` @10292 对 43 个品种逐个调 `load_daily_refreshed(sym)`（`four_dim_strategy.py:1576`，`ttl=1800`）
- 该缓存按**品种首次加载时刻**起算 → 启动时 43 个品种在同一轮集中首载 → 约 30 分钟后**同一轮集体过期**
- 过期轮串行重拉 tqsdk + akshare 兜底 → 冲出 105 秒

元问题：**全系统没有任何每轮耗时埋点**（`grep cycle_ms|elapsed|perf_counter` 无命中于主循环）。因此周期退化只能靠外部采样发现，无法定位到环节。

### 🟡 R3 配置假开关

`feature_flags.json` 里只有 **6 个** flag 真被 `is_enabled()` 读取：
`auto_optimize / decorrelate / market_state_engine / robust_pool_gate / seasonal_boost / trailing_stop`

其余（`drawdown_guard` / `kill_switch` / `corr_gate` / `notify` / `signal_explain_llm` / `tick_connector` / `take_profit_state_machine`）**UI 上可切、实际无效**。

2026-09-08 已发现此问题，两个月后的处理方式是给文件加 `"_wired": false` 字段做**标注**，而不是修复或移除。标注诚实 ≠ 一致。

### 🟡 R4 端点与代码膨胀

- 后端 82 个端点，**16 个前端从不调用**：`account_heal / accounts / auto-optimize / cgate / consistency / contracts / decompose / feeddebug / ga_weights / market-state / position_levels / positions_reconcile / recalibrate / report_weekly / rollover_mismatch / trisense-replay`
- 单体 15,915 行，导入 30+ 模块，`start_dashboard()` 内嵌 3,000+ 行
- 命名分裂：对外"三感参谋"，代码全 `four_dim`，**"三感"在代码里无任何定义**

### 🟡 R5 数据与备份堆积

| 项 | 体量 | 性质 |
|---|---|---|
| `tick_stream.jsonl` | **232 MB** | 无轮转、无压缩、24h 增长 |
| `watchdog.log` | 15.5 MB | **2026-11-01 后停更 = 死文件** |
| `four_dim_live_runner.py.bak*` ×3 | 1.8 MB | 手工备份 |
| `_backup_before_truth_sync_*` ×5 | 0.1 MB | 一次性快照 |
| `_backup_clear_20261023_115125/` | 28.9 MB | 旧仓库整份 |
| `coverage-html/` | 23.1 MB | 测试覆盖率报告 |
| `papertrack_dashboard.html` | 898 KB | 与主面板功能重叠 |

合计可回收约 **300 MB**（不含 tick_stream 保留策略）。

## 4. 升级方向与理由

### 方向 A：账户层收敛为单一真相源（SSOT）— P0

**理由**：这是唯一一条"不修就会持续算错仓"的问题。权益错了，四层风控全部失效但**不会报错**——系统会自信地给出错误手数。危险等级高于主循环超时：超时会死给你看，口径错不会。

**原则**：
- 一套账本、一个 `source` 枚举、一条回退链，且**禁止 `static_fallback` 进入 sizing 路径**
- 活不了的账本删除，不留"名义账本"
- 真实权益取不到时**宁可不出信号**，也不要用常量冒充

### 方向 B：主循环分级调度 + 全链路埋点 — P0

**理由**：105 秒距 180 秒自杀线只剩 40% 余量，而 11-04 已经死过一次。且没有埋点就无法证明修好了——只能靠外部采样猜。

**原则**：
- 每轮分环节计时，输出到 `/api/health`，让"慢在哪"变成可观测事实
- 慢变量（日线）与快变量（5m/实时价）分离调度，日线 TTL 打散 jitter，消除集体过期
- 43 品种分批评估（按板块轮转），单轮只重算 1/3

### 方向 C：配置去伪 + 端点与命名收敛 — P1

**理由**：假开关比没开关更危险——它会让人以为切了。UI 上的开关必须是真开关，否则删掉。

### 方向 D：从"信号发生器"升级为"策略分账系统" — P2（战略）

**理由**：系统现在能回答"现在该做什么"，**回答不了"哪套打法真的在赚钱"**。
当前四条腿全部 `source=auto_signal`，混在一个账户里，无法区分是四维信号的贡献还是手动/跨期的贡献。这也是 2026-11-05 讨论《151 Trading Strategies》时暴露的真正缺口——不是缺策略，是缺**按收益来源分账**的能力。

## 5. 可落地功能要点（含验收判据）

### F1 · 单一账户真相源
- **输出**：`account_truth.json`，字段 `{equity, positions[], source, synced_at, stale_sec, chain[]}`
- **source 枚举**：`live_broker` / `live_snapshot` / `manual_anchor` / `paper`——**不含 static**
- **判据**：`/api/state.sizing_equity.source` 不得出现 `static_fallback`；若全部来源失效，`risk_gate` 返回空信号并在面板红字告警
- **验收**：连续 3 个交易日 `source ∈ {live_snapshot, manual_anchor}`；`/api/account?fresh=1` 冷算 < 3 秒
- **附带**：删除 `account_state.json`（或降级为 `positions` 只读镜像，不再承载 equity）

### F2 · 主循环分级调度 + 耗时埋点
- **输出**：`/api/health` 新增 `cycle_breakdown: {poll, evaluate, market_state, aux, pti, tri, reconcile, io_persist, total}`，保留最近 30 轮
- **做法**：
  1. 日线 TTL 加 `±600s` 随机 jitter（同一品种稳定，跨品种打散）
  2. 日线刷新移出 `evaluate()` 临界区，改后台预热
  3. `SYMBOLS` 按板块分 3 批，每轮只全量算 1 批 + 其余用缓存
- **判据**：连续 24 小时 `max(cycle) < 75s`、`p95 < 65s`、无 `_stall_watchdog` 触发
- **验收**：`grep "停摆" launchd.log` 增量 = 0，且 `cycle_breakdown` 有数据

### F3 · 配置与端点去伪
- **做法**：`feature_flags` 只保留 6 个真接线项；其余从 UI 移除并在文件标 `"deprecated"`。16 个死端点逐个标 owner（运维 / 自动化 / 废弃），废弃的删除
- **判据**：前端可见开关数 == `is_enabled()` 实际读取数（6）
- **验收**：`grep -c 'is_enabled'` 与 UI 开关数一致；后端端点 ≤ 70

### F4 · 数据轮转
- **做法**：`tick_stream.jsonl` 按日切分 + gzip，保留 7 天；`watchdog.log` / `launchd.log` / `runner.log` 纳入同一轮转器
- **判据**：项目总体积 < 400 MB，且 7 天内 tick 可回溯
- **验收**：`du -sh` 实测；抽查 T-7 日的 tick 文件可解压读取

### F5 · 策略分账（承接 151 讨论）
- **做法**：每条持仓腿打 `strategy_tag`（`four_dim` / `mr_ensemble@5m` / `manual` / `calendar_spread`）；新增 `/api/attribution` 按 策略 × 板块 × 时段 输出 expR / 胜率 / 笔数 / 手续费占比
- **判据**：能回答"这个月四维信号贡献了多少 R、手动干预亏了多少 R"
- **验收**：`/api/attribution` 返回的 ΣexpR 与 journal 净盈亏闭合（误差 < 1 个手续费单位）

## 6. 执行顺序与预期效果

| 批次 | 内容 | 前置 | 预期效果（目标，非承诺） |
|---|---|---|---|
| **第 1 批** | F1 账户 SSOT | 11-09 收官 | sizing 脱离硬编码；四层风控恢复真实口径；account 冷算从 25–38s 降到 <3s |
| **第 2 批** | F2 埋点 → 再调度 | F1 后（埋点先上，用 3 天数据定调度方案） | 周期 p95 < 65s，摆脱 180s 自杀线；慢在哪变成可观测 |
| **第 3 批** | F3 + F4 | 可与第 2 批并行 | 开关不再骗人；体积从 816MB 降到 <400MB |
| **第 4 批** | F5 分账 | 有 ≥2 周带 tag 的成交数据 | 能按收益来源排序，为 151 那套 7 维评分提供真实输入 |

**为什么 F1 排第一**：它是唯一"不修就持续算错、且不报错"的问题。F2 排第二是因为它已经死过一次且有明确余量告急——但**必须先有埋点再动调度**，否则改完无法证明有效，等于把不确定性从一处搬到另一处。

**为什么 F5 最后**：分账需要历史 tag，今天之前的数据没有，只能从打 tag 那天开始攒。

## 7. 明确不做

- ❌ **不做自动下单**：接入券商 API 前，半自动边界不动
- ❌ **不动前视偏差隔离线**：五个 live-only 调制器不得进入回测路径
- ❌ **不在窗口内（11-02→11-09）改任何代码/配置/状态文件**
- ❌ **不做"大重写"**：15,915 行一次性拆解的风险远高于收益，按 F1–F5 增量推进
- ❌ **不为了"架构好看"而拆模块**：拆的前提是可测（有测试覆盖 + 有埋点）
