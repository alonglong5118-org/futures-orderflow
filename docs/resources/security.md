# 安全策略

我们非常重视项目的安全性。本文档说明安全漏洞的报告方式、响应流程以及安全最佳实践。

---

## 报告安全漏洞

如果您发现了任何安全漏洞，请**不要**在公开的 Issue 中报告，而是通过以下方式私下联系我们：

### 方式一：GitHub 安全咨询（推荐）

通过 GitHub [发起安全咨询](https://github.com/alonglong5118-org/futures-orderflow/security/advisories/new)

### 方式二：邮件

发送邮件至安全联系人邮箱（请在项目 README 或组织主页中查找最新联系方式）

### 请提供以下信息

- 漏洞类型（如：注入、权限绕过、信息泄露等）
- 漏洞的详细描述和复现步骤
- 受影响的版本范围
- 可能的影响和严重程度评估
- （可选）修复建议

---

## 响应流程

收到安全漏洞报告后，我们将按照以下流程处理：

1. **确认收到**（24 小时内）：确认收到您的报告，并指派专人跟进
2. **漏洞评估**（1-3 个工作日）：评估漏洞的严重程度和影响范围
3. **修复开发**：根据严重程度安排修复
    - **严重/高危**：优先处理，尽快发布安全补丁
    - **中危**：纳入下一个版本迭代
    - **低危**：视情况安排修复
4. **发布补丁**：修复完成后发布安全更新版本
5. **公开致谢**：在安全公告中致谢报告者（如您同意）

---

## 安全公告

安全漏洞修复后，我们将通过以下渠道发布公告：

- GitHub Releases（附带安全标签）
- 项目 Security Advisories 页面

## 受支持的版本

当前安全修复仅适用于以下版本：

| 版本 | 支持状态 |
|---|---|
| 最新稳定版 | ✅ 完全支持 |
| 前一个次要版本 | ⚠️ 仅高危/严重漏洞 |
| 更早版本 | ❌ 不再支持 |

建议始终使用最新稳定版本以获得最佳的安全性保障。

---

## 安全最佳实践

为确保使用安全，建议用户遵循以下最佳实践：

### 1. 及时更新

- 关注项目 Release，及时升级到最新版本
- 启用 Dependabot 自动接收依赖更新
- 定期运行 `pip-audit` 审计依赖安全

### 2. 密钥管理

- **不要**将 API 密钥、交易密码等敏感信息提交到代码仓库
- 使用环境变量或 `.env` 文件存储敏感信息（`.env` 已加入 `.gitignore`）
- 为交易 API 密钥配置最小权限
- 定期轮换密钥

### 3. 最小权限原则

- 交易 API 密钥只授予必要的权限
- 运行环境使用独立的低权限账户
- 限制网络访问范围

### 4. 网络安全

- 确保运行环境的网络安全
- 避免在不可信环境中运行
- 使用加密连接访问交易接口

### 5. 实盘防护

- 先用模拟盘充分验证策略
- 实盘从小资金开始
- 设置好风险门禁和止损规则
- 定期检查系统运行状态和账户对账

## 安全检查机制

项目内置多层安全检查：

| 检查项 | 工具 | 说明 |
|---|---|---|
| 代码语义分析 | CodeQL | 检测潜在安全漏洞 |
| 密钥泄露检测 | Gitleaks | 防止敏感信息提交到仓库 |
| 安全评分 | Scorecard | 开源项目安全健康度评分 |
| 依赖安全审计 | Dependabot | 自动提交依赖安全更新 PR |
| Python 安全扫描 | Bandit | Python 代码安全问题检测 |
| SBOM 生成 | 内置 | 发布时生成软件物料清单 |
