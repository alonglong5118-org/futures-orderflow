    """委托 account_ssot：唯一真源，无静态兜底。"""
    acct = _STRAT_CFG.get("account", {})
    mode = "paper" if _PAPER_MODE else "live"   # 新增：由 trade_config.account.mode 决定
    r = account_ssot.resolve(

## 2. B · 主循环耗时

### 2.1 探针（已交付，只读）与它抓到的实测基线

`staged_upgrade/cycle_probe.py`：每 2 秒抓一次 `/api/health.last_cycle_ago_sec`，用「数值回落」推出一圈真实耗时，
按看门狗 180 秒线分级（<100 绿 / 100–150 黄 / >150 红 / >175 红红），结果追加进 `cycle_history.jsonl`。

**10:42:35–10:52:35 的 10 分钟实测（这是第一次拿到分布而不是点估计）**：

```
采样 266 次，抓到 3 个完整周期
周期 p50 = 103.7s   min = 102.0s   max = 141.6s
max_cycle_ago = 189.9s  →  🔴 越过 180s 自杀线
18 次探测无响应（HTTP 6s 超时）
```

结论：**周期不是"偶尔慢"，是常态 100 秒以上**（设定 60 秒），且存在 141 秒的尖峰。
189.9 秒之后就是 `[看门狗] 主循环已停摆 191s，自杀退出`。

### 2.2 三个代码级缺陷（静态定位，不是猜测）

| # | 位置 | 缺陷 | 后果 |
|---|---|---|---|
| **B-1** | `minishare_live.py` L745–768 | `poll()` 里对**全量 rt_fut_k 快照**跑两次 `df.iterrows()`：一次在 `_refresh_hot_contracts(df)`（L762），一次在主循环（L768）；且 `_refresh_hot_contracts` **每次 poll 都重解析全部品种主力合约**（L589）。日志里 `[minishare_live] 主力合约解析` 实测 **13 行/62 秒**，即每次 poll 都打印 | poll 由独立线程 `ak_poller` 约 5 秒一次驱动，持续吃 CPU 并**持有 GIL**。Python 单进程下，这将与主循环线程抢 GIL，**间接**拉长主循环耗时。⚠️ 这是机制推断，不是已证明的因果——没有埋点就无法定量，见 §2.3 |
| **B-2** | `four_dim_strategy.py` L1620–1646 | `load_daily_refreshed` 分支 2（常规品种）**只在抓取成功时**才写 `_DAILY_CACHE`（L1629 / L1644）。tqsdk 与免费源同时失败 ⇒ 缓存**永远不写** ⇒ **每一轮都重跑整条抓取链** | ⚠️ **潜在风险，当前未发作**：日志里 `[daily refresh]` 失败行 **0 条**，说明今天抓取全部成功、缓存正常写入。但一旦某个源被 IP 限流（历史上发生过），这个缺陷会把它变成「每轮重试」→ 周期立刻顶到 180 秒线。属于一击致命的隐患，不是现行病因 |
| **B-3** | `four_dim_strategy.py` L1578 | TTL 固定 1800 秒，**无 jitter**；43 品种启动时集中加载 ⇒ 30 分钟后同一轮集体过期，串行重拉 | 能解释 141.6 秒这类尖峰，但解释不了 p50 就有 103.7 秒（常态慢说明还有稳定开销） |

**这份清单最重要的作用是说明一件事：三个候选机制都存在，但没有一个能在现有证据下被判定为「主因」。**
p50 = 103.7s 意味着每轮稳定多花 40 秒以上，而日志里没有任何每轮耗时的痕迹——
这正是 §2.3 埋点必须先上的原因。**在没有埋点前动手改调度，等于蒙着眼睛修表。**

`sample 41270` 的 6 秒采样佐证：主线程全在 `nanosleep`（说明循环本身在睡，慢在循环体内），
其他线程热点是 `scan_once_unicode`（JSON 解析）、`_io_FileIO___init__` / `_Py_read`（大量文件重读）、
`PEM_read_bio_ex`（新建 TLS 连接）——与 B-1/B-2 的「重复读文件 + 重复连网」一致。

### 2.3 埋点补丁（**现在成了第一优先级**）

`/api/health` 增加字段：

```python
state["cycle_breakdown"] = {
    "ts": now_iso,
    "total_ms": int((time.perf_counter() - _t_cycle) * 1000),
    "poll_ms": ..., "evaluate_ms": ..., "pti_ms": ..., "aux_ms": ..., "io_ms": ...,
    "daily_fetch_n": _DAILY_FETCH_COUNTER,     # 本轮真正抓日线的品种数
    "daily_cache_hit": _DAILY_CACHE_HIT,       # 命中数

```

配套：`_DAILY_FETCH_COUNTER` 在 `load_daily_refreshed` 的两个抓取分支里 +1，函数返回前清零到 state。
**没有 `daily_fetch_n`，就无法判断 B-2 是不是真因——改完也无法证明有效。**

## 5. E · 策略分账（功能已存在一半，问题是一行代码）

### 5.1 真相

`/api/journal_strategy` **已经实现**（runner L12047，`tj.by_strategy`），前端也在调（`four_dim_live.html` 里 3 处）。实测：

```
?group_by=account  → {"groups":[{"group":"paper","total":4,"closed":1,"open":3,
                                 "wins":0,"win_rate":0.0,"pnl":-2918.96}]}     ← 有数据
?group_by=strategy → {"groups": []}                                            ← 永远空
```

根因在 `trade_journal.py` L949 一行：

```python
trades = data.get("trades", []) if (include_paper or group_by == "account") else _live_rows(data)
```

按 account 分组时包含模拟盘；按 strategy 分组时走 `_live_rows()` **排除 paper**。
而当前 4 笔成交全部是 `account="paper"` ⇒ 按策略聚合恒为空。
且端点从不传 `include_paper`，所以这个参数形同不存在。**`?account=paper` 也一样**：
`/api/journal` 只把它当缓存键（L11976），`tj.summary()` 调用时不带参数，仍按实盘口径返回全零。

### 5.2 修复（总计 3 处小改，不改数据结构）

1. **端点透传**（runner L12047，2 行）：
   ```python
   _ip = _q.get("include_paper", ["0"])[0] in ("1", "true", "yes")
   body = json.dumps(tj.by_strategy(group_by=_gb, include_paper=_ip), ...)
   ```
   同理 `/api/journal` 把 `account=` / `include_paper=` 真正传给 `tj.summary(account=..., exclude=None)`。

2. **`strategy` 枚举化**（写入侧）：现在 journal 里写的是自由文本「引擎自动」，信号表里写的是「趋势 / 手动」，
   两套互不认。改为固定枚举 `four_dim_trend` / `mr_ensemble` / `calendar_spread` / `manual`，
   且 journal 写入时**透传信号的 strategy**，不再自造。

3. **主键打通**：`trade_journal` 有 `signal_id`（如 `239978edc5608b98`），但 `four_dim_signals.json`
   的信号对象**没有 `id` 字段** ⇒ 无法 JOIN。给信号加 `id` 并让 journal 直接引用。

**回填**：现存 4 笔只能按 `(symbol, 时间 ±2 分钟, 方向)` 近似匹配（例：PK 13:34:01 ↔ 信号 13:32:58）。
可做，但要做衰减标注，别当成精确归因。

### 5.3 验收

- `/api/journal_strategy?group_by=strategy&include_paper=1` 返回非空，且 `Σ net_pnl` 与 journal 明细闭合
- 每条新成交都能用 `signal_id` 精确回指信号，**不再靠时间窗猜**
- 面板上「按策略 / 按板块 / 按时段」三张表都能出数——这才是 151 那轮讨论的真正落点：
  **不缺策略，缺按收益来源分账的能力**
