## 1. 正式分层

| 层 | 回答的问题 | 本系统谁干这活 | 输出 |
|---|---|---|---|
| **定位层** | 做哪个品种、什么方向 | 三感参谋的 F/T/C → `bias_G` → 触发判定 | 方向（多/空） |
| **风险层** | 做多少、何时认错 | 风控四层 + `exit_plan()` | 手数 / 止损 / T1/T2 |
| **执行层** | 此刻进不进、挂在哪 | 订单流面板（tick Delta / OFI / 吸收） | 挂单价 / 进场确认 |

> **禁止：用执行层替换定位层。**
> 三感参谋覆盖 **54 品种定义 / 43 活跃**（`four_dim_strategy.py:174` SYMBOLS，`:272` DISABLED_SYMBOLS）；
> 订单流实盘可盯品种受 **tick 源可得性 + 盯盘带宽** 双重限制（当前配置 6 个，见 §3）。
> 二者覆盖面相差约 **7–27 倍**。放弃三感参谋「全力转订单流」= 用最窄的一层替换最宽的一层。

## 2. 冲突裁决规则（R1–R5，写死）

> 场景：三感参谋给出方向 D1，订单流给出方向 D2，**D1 ≠ D2**（含订单流中性）。

| 规则 | 内容 |
|---|---|
| **R1 · 风险层单向否决（最高优先）** | 风控四层任一否决/降级（KillSwitch、回撤档、连亏锁定、`DISABLED_SYMBOLS`）→ **一律不开仓**。订单流看到什么都不能覆盖。 |
| **R2 · 同向 → 只优化时机** | D1 = D2 时，订单流**仅**用于优化**进场时机与挂单价**；**不得**改变方向、手数上限、止损位。 |
| **R3 · 反向 → 默认弃单，禁止反手** | D1 ≠ D2 时，**放弃该笔**。**禁止**用订单流单独反手开仓。 |
| **R4 · 例外须预注册** | 若要允许订单流反向主导，必须先**预注册判据 + 跑 edge 验证**（§4），通过后方可登记例外条目，且限定品种 / 时段。 |
| **R5 · 冲突留痕** | 每次 R3 弃单须落一条审计记录（时间 / 品种 / D1 / D2 / 处置），供后续统计冲突频率。 |

**R3 的理由**：反手 = 让执行层越权决定方向 → 系统退化为「盯盘手」，且丧失可复现性。方向授权在定位层，订单流**只有时机授权**。

## 3. 订单流品种边界（写死）

| 品种 | 交易所 | 夜盘 | tick 可得性 | 裁决 |
|---|---|---|---|---|
| 玻璃 FG / 纯碱 SA | CZCE | 有 | 免费源**真实 tick** ✅ | **可用（全流程）** |
| 焦煤 JM / 焦炭 J | DCE | 有 | 免费源无 tick → akshare **分钟回退** | **降级可用**（分钟近似，非真 tick；吸收 / OFI 精度受限） |
| 鸡蛋 jd / 生猪 lh | DCE | **无** | — | **不上**（无夜盘 + 流动性薄 → tick 稀疏 → 信噪比显著劣化） |

**判据**：订单流信号依赖 **tick 密度 × 盘口深度**。
- 无夜盘 = 每日少 2 小时连续成交；
- 流动性薄 = 主动流稀疏、盘口挂单薄；
- 二者叠加 → Delta / OFI / 吸收的**信噪比显著劣化**。

### ⚠️ 当前配置与边界不符（已登记，待处置）

- `backend_tqsdk.py:44` `SYMBOL_MAP` 现含 **6 个品种**（FG / SA / JM / J / **jd** / **lh**）——**jd / lh 仍在喂入**（akshare 分钟回退）。
- tick feed **默认关闭**：`four_dim_live_runner.py:567` `TICK_FEED_ENABLED` 默认 `"0"`；未开启时 `C_flow` 由 minishare 驱动（`:14619`）。
- **剔除 jd / lh 属信号行为改动** → 须按 README「策略改动铁律」跑 `tools_regime_ab.py` 全品种 A/B，**不得直接改**。

## 4. 执行层启用的前置条件（预注册）

> **2026-10-04 决策：订单流只做「事后复盘」，不做实时决策。**
> 理由：21:00–23:00 已是三重占用（4 品种夜盘 + 六份日报 + 内容生产），当前真正缺的是「这套信号到底有没有 edge」的证据，不是下单能力。

启用实时执行层前，须先满足：

1. **数据**：已录 tick（FG / SA 真 tick）
2. **指标**：吸收信号出现频率 + 信号后 **5 / 15 分钟方向命中率**
3. **基准**：**随机基准**（同期同品种随机入场命中率）
4. **判据（跑之前定死）**：命中率**不显著优于随机基准 → 订单流止步研究层**，不支付「极高盯盘专注度」这个代价
5. 任何结论**必须声明样本量与时间窗**

> 在 §4 通过前，订单流**不参与任何实时决策**，包括 R2 / R3。

## 5. 观测 ≠ 推断（防止过度声称）

| | 内容 |
|---|---|
| **可观测** | 主动 / 被动成交、累计 Delta、盘口失衡、撤挂 |

## 6. 已知局限：C（订单流）维度在回测中恒为 0

> 2026-10-04 实测结论（详见 `全品种回测复核_20261004.md`）。

| 实测项 | 结果 |
|---|---|
| `precompute_C_array(sym)`（dragon 源） | FG / SA / jd / lh / cu **非零个数全部 = 0** |
| `precompute_C_array(sym, c_source="kline")` | 同样 **全部 = 0** |
| `cflow_kline_cache.json` | **不存在** |

**含义**：`bias_G = 0.6T + 0.25F + 0.15C`，但**回测中 C ≡ 0** → 历史上所有回测结论实质是 **F + T 两维**。

→ **凡引用回测数字时，不得表述为「订单流策略的表现」**；订单流（C）当前只活在**实时链路**与 §4 待跑的事后复盘里，尚未进入任何回测基线。
→ 若要 C 真正进回测，须先补齐 `cflow_kline_cache.json`（17 年 K 线资金流）或龙虎榜历史映射，**再**重跑基线。
