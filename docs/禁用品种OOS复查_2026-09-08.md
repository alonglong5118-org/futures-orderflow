# 禁用品种（DISABLED_SYMBOLS）OOS 复查报告

> 生成日期：2026-09-08　|　工具：`tools_disabled_oos_recheck.py`
> 结论：**11 个被禁品种全部维持禁用，无一个达到解禁标准。**

---

## 一、背景

`DISABLED_SYMBOLS`（11 个：au / i / eg / m / a / b / rr / RM / hc / MA / PR）的判死依据
是 `calibration_params.json` 的历史 `mean_oos`。但 v1.2.2「28 品种重校准」大改了
`T_thresh` 后，**禁用清单从未随之重跑**，存在「误杀」嫌疑。

2026-09-07 通读时用**全历史口径**（含样本内）实测，发现 11 个禁用品种中 8 个正期望
（合并 +0.0965R，n=872），一度怀疑大面积误杀。

⚠️ **但该口径不合法**：禁用依据是 `mean_oos`（样本外），全历史实测含样本内，
两者不可直接比较。本报告改用**同口径样本外**重跑，结论相反。

## 二、方法

三重判定，脚本 `tools_disabled_oos_recheck.py`：

| 口径 | 定义 | 作用 |
|---|---|---|
| **A** | `recovery_check(tail=250)` —— 系统自带解禁标准（expR≥0 且 胜率≥45% 且 n≥10） | 与既有机制对齐 |
| **B** | 真·样本外：数据**后 1/3 切片**，用当前 `DEFAULT_CONFIG` 直接评估 | 主判定（样本量更大、无样本内污染） |
| **C** | 40 个活跃品种在**同一 B 口径**下的 expR 分布 | 解禁基准线 |

判定规则（保守，遵循「无证据默认不改」）：

- **建议解禁** = A 通过 **且** B 的 expR > 0 **且** B 的 expR ≥ 活跃品种中位数
- **观察** = A 或 B 其中之一为正，但未达解禁线
- **维持禁用** = 其余

## 三、结果

### 活跃品种基准线（口径 B，同切片）

- 40 个品种，**中位数 +0.3402R**，等权均值 +0.8594R，**交易量加权 +0.4920R（n=658）**
- 正期望 31/40（77.5%）
- 注：均值远高于中位数，因小样本品种（如 cu n=3 报 +4.74R）拉高，属噪声，
  **故以中位数 +0.3402 作为解禁基准线**

### 11 个被禁品种

|---|---|---|---|---|---|---|---|---|---|

| RM | −0.2722 | 25.0% | 4 | 样本不足 | +0.0865 | 33.3% | 27 | −0.2537 | 观察 |

**汇总**

- 建议解禁：**0 个**
- 观察：6 个（m / a / rr / hc / RM / b）
- 维持禁用：5 个（MA / PR / au / eg / i）
- 禁用品种 pooled 样本外 expR = **+0.1050R（n=294）**
  vs 活跃品种 **+0.4920R（n=658）** —— 差距 **−0.387R**

## 四、结论

**不存在误杀，维持全部禁用是正确的。**

最接近基准线的是 **m（+0.3392 vs 中位数 +0.3402，差 −0.0010）** 和
**a（+0.3240，差 −0.0162）**，但均未达标。按「无证据默认不改」铁律，
**不修改 `DISABLED_SYMBOLS`**。

### 对 2026-09-07 初步印象的修正

| | 2026-09-07 初判 | 2026-09-08 复核 |
|---|---|---|
| 口径 | 全历史（含样本内） | 后 1/3 真样本外 |
| 正期望品种 | 8/11 | 6/11（且全部低于基准线） |
| 结论 | 疑似大面积误杀 | **无误杀** |

教训重申：**评估禁用/启用必须与判死依据同口径**，
禁用依据是 `mean_oos`（样本外），就不能拿全历史实测去比。

## 五、附带发现（两个真问题，未修）

### 1. `recovery_check` 自适应恢复机制形同虚设

- **A 口径 10/11 个品种因「样本不足（n<10）」无法判定**，最大 n 仅 11（i）。
  日线策略 250 根窗口（≈1 年）本就只有几笔成交，`min_trades=10` 几乎不可达。
- 且 `AUTO_RECOVER_SYMBOLS = {"hc"}` —— 11 个里只有 hc 参与周期性复查，
  其余 10 个**硬禁永不复查**。
- 综合结果：**自适应恢复从未真正生效过**。

⚠️ 风险提示：若单纯放宽 `min_trades` 或放大窗口让机制「活过来」，
hc 会被放行（A 口径 expR +0.4462 / 胜率 50%），但 hc 的真·样本外只有 +0.2137，
低于活跃中位数 —— **即机制活化反而会放行低质量品种**。
且 A 口径（近期窗口回测）用的配置是在全历史上调的，**天然含样本内优势**，
比 B 口径乐观得多。故**本次不修**，需专项评估后再定。

### 2. `calibration_params.json` 值陈旧（展示层）

禁用清单既然维持，判死依据本身是否可信反而成了次要问题；
但该文件驱动 `/api/edge` 展示，值与当前配置严重脱节（hc 校准 −0.615 vs 样本外 +0.2137），
建议重跑校准刷新展示值 —— 属**展示层维护**，不改变策略行为。

## 六、复现

```bash
python3 tools_disabled_oos_recheck.py                 # 全量（含活跃基准线）
python3 tools_disabled_oos_recheck.py --no-baseline   # 跳过基准线（更快）
python3 tools_disabled_oos_recheck.py --symbols hc m  # 指定品种
python3 tools_disabled_oos_recheck.py --tail 500      # 改 A 口径窗口
```

输出：`/tmp/disabled_oos_recheck.json`
